# ZK-Voting L2

**NOT FOR PROFIT** — civic public good. Not a commercial product. See [`NOT_FOR_PROFIT.md`](./NOT_FOR_PROFIT.md).

Civic votes run on an application-specific ZK rollup in the [Lighter](https://lighter.xyz) /
zkSync Lite pattern:

- **Ethereum L1** settles and enforces the rules through **one contract for the world**,
  `ZkVotingRollup`. It holds jurisdictions, elections, guardian keys, the batch chain, the
  priority queue and the certified results.
- An **L2 operator** (`l2/rollup`, the `l2` Compose service) orders ballots and roll changes into
  batches and commits them to L1, where each batch must carry a validity proof.
- The **Node** publishes civic votes, syncs their rolls, relays guardian messages and passes
  voters' encrypted ballots to the operator.

Polls do not use the L2; they run on the Node.

Design and every rule the contract enforces: [`smart-contracts/docs/ROLLUP.md`](../../smart-contracts/docs/ROLLUP.md).
Operator internals and its HTTP API: [`l2/README.md`](../l2/README.md).

## What the operator can and cannot do

| Can | Cannot |
| --- | --- |
| Order ballots and roll changes into batches | Create an election, change a roll, or invent a result |
| See ballot ciphertexts and their arrival times | Decrypt a ballot alone (needs a threshold of guardians) |
| Stall (stop committing) | Censor a voter: a refused ballot can be forced in through L1 (`forceBallot`) |
| Revert its own unexecuted batches | Skip the L1 priority queue: after 3 days anyone can trigger **desert mode** |

In desert mode the rollup is frozen for good; elections that already closed finish normally, and
an open election can be closed once from the last proven state (`desertClose`).

## What is public

A ballot reaches L1 only as a nullifier and a hiding commitment in batch pubdata. The operator's
API never returns a ciphertext, a live ballot count or a partial sum. The only ciphertext L1 ever
decrypts is an election's final per-option sum. Batch pubdata does show how many ballot
operations each batch carried, so turnout over time is public at batch granularity.

## Running it

In Docker Compose the `l2` service runs `node rollup/main.mjs`. It needs:

| Variable | Purpose |
| --- | --- |
| `L1_RPC`, `L1_CHAIN_ID` | The L1 it settles to |
| `L1_RPC_AUTH_TOKEN` | Optional bearer token when that RPC requires auth. Empty sends no Authorization header. |
| `ROLLUP_ADDRESS` or `ROLLUP_DEPLOYMENT_FILE` | The ZkVotingRollup it follows |
| `OPERATOR_PRIVATE_KEY` | An account registered with `setOperator`; it pays L1 gas for batches |
| `L2_BALLOT_TOKEN` | Bearer token the Node presents on `POST /v1/ballots` |
| `L2_BATCH_SECONDS` | How often it checks for work (default 10) |
| `L2_ALLOW_DEGRADED` | Empty or `false` (default): exit if startup checks fail. `1`: stay up in degraded mode, serve `/health`, and retry without submitting to L1 |
| `L2_BATCH_MAX_WAIT_SECONDS` | How long ballots wait for a fuller batch (default 0 on chain 31337, 600 elsewhere); never past a cutoff |
| `ZK_VOTING_ALLOW_MOCK_PROOFS` | Chain 31337 only: accept ballots without an eligibility proof |

Outside Docker: `npm run l2:operator` from `voting_node/`.

State is one file, `rollup-operator.json`, on the `l2-data` volume: the state tree, ballots not
yet in a batch, receipts and batch history. Back it up ([Backups](./self-hosting/backups.md)).
The operator has no writer lease: run one at a time and recreate its container to update it.
While it is down the Node answers ballot requests with 503 and voters retry.

## Not built yet

The **batch validity circuit** (with recursive verification of each voter's ballot proof and the
roll-membership proof) is specified but not built. Until it is, the rollup settles only against
`MockBatchVerifier` on the local chain (31337). Without `L2_ALLOW_DEGRADED` the operator
exits against a real verifier. With the flag on it stays up in degraded mode and does not
submit batches. A public-chain civic vote is therefore not possible yet.
